# Percí v1.6 · Criterios de aceptación y QA de entrenamiento

**Hipótesis UX:** una persona que está entrenando debería poder recordar la última carga, completar una serie y visualizar su avance sin navegar a Progreso durante la sesión. Una persona que crea ejercicios personalizados debe poder hacerlo sin desplazarse por toda la biblioteca.

## Criterios funcionales

- [x] El formulario de ejercicio personalizado aparece antes del buscador y lista, únicamente cuando se edita una rutina.
- [x] Se puede ingresar un nombre por teclado móvil y añadirlo pulsando Enter o el CTA.
- [x] La serie siguiente se destaca; solo `done===true` incrementa progreso y volumen.
- [x] Referencia de peso/reps de la última serie comparable por nombre y número, dentro de la cuenta actual; copiar es acción explícita.
- [x] Descanso por defecto desactivado; 60/90/120 s; se guarda en draft local con fecha límite UTC; no requiere background activo.
- [x] Resumen al finalizar desde el registro persistido, sin duplicar un entrenamiento.
- [x] Evolución por ejercicio desde detalles completados y no desde datos de muestra; cero datos presenta estado vacío contextual.
- [x] `volume` preserva hasta dos decimales, compatible con el `numeric(14,2)` actual de Supabase.
- [x] URLs JS de la PWA y caché unificadas a v1.6, con pruebas de integridad.
- [x] No hay cambio en endpoints, Supabase, credenciales ni políticas existentes.

## Comprobación de regresión local

- 93 pruebas JavaScript en `npm test` (incluye render real de funciones de vistas en Node y tests de cálculos puros).
- 43 pruebas Python en `python3 -m unittest discover -s tests -p 'test_*.py' -q`.
- Verificación `node --check`, `python3 -m py_compile` y limpieza de archivos de test privados antes de armar el ZIP.
