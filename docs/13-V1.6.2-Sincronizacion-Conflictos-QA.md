# Auditoría de reconciliación v1.6.2

## Caso reproducido

Mac: baseline `TEST MAC 2`, estado local `TEST MAC 2`. iPhone: decide `TEST IPHONE 2`, que queda como estado remoto. Antes, la conciliación de dos vías detectaba el mismo ID con contenido diferente y obligaba a elegir otra vez en Mac.

## Regla

Para el mismo usuario, usar última versión conocida como ancestro común:
- Local = ancestro, remoto diferente ⇒ **aplicar remoto sin conflicto**.
- Remoto = ancestro, local diferente ⇒ conservar local, respetando cola pendiente.
- Ambos diferentes del ancestro y entre sí ⇒ **conflicto verdadero**, pedir decisión.
- No hay baseline ⇒ conservar la precaución anterior.

`reconcileCloudWithBaseline` es una función pura cubierta por tests. El estado UI lo gestiona `hydrateCloud` en la ruta **sin outbox** y también `chooseCloudConflict` para la resolución.

## Evidencia automatizada

Consultar `tests/cloud-conflict-dedup.test.mjs`: cambios solo remotos, conflicto verdadero, agregado remoto, falta de baseline, nube vacía y borrado remoto, además del enlace del helper en las dos rutas de UI.
